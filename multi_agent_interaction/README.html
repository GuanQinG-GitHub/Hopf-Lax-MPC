Interacting agents: Hopf–Lax-MPC with pairwise collision avoidance

Extension of ../multi_agent. The K agents there are decoupled. In the recorded decoupled runs, pairs come within 0.65 m (K = 2), 0.31 m (K = 3), 0.12 m (K = 4) and 0.01 m (K = 10).

Here the running cost gets a soft pairwise collision penalty. This couples the agents through the costate equation, so the K rollouts become one joint rollout and the Jacobians become dense. The algorithm (core/mpc_solvers.hopf_lax_mpc_solve) is still run unchanged. The solver object works for any number of agents; K = 2, 3, 4 are tested.

2. Coupled problem: cost, Hamiltonian, canonical system

The notation is that of ../multi_agent/README.md sections 2–5: agent k has state $x_k\in\mathbb R^7$, position $q_k = [p_x,p_y,p_z]_k$, costate $p_k$, single-agent running cost $L_k$ (tracking, control and obstacle barriers), terminal cost $\phi_k$ and dynamics $f$ (dyn7).

Pair penalty. For a safety radius $R_c$, weight $W_c$ and shell width $w_c$, in the same tanh family as the obstacle barriers:

$$ r_{ij} = \sqrt{\frac{\|q_i-q_j\|^2}{R_c^2}+\varepsilon},\qquad z_{ij} = \frac{r_{ij}-1}{w_c},\qquad C(q_i,q_j) = \frac{W_c}{2}\big(1-\tanh z_{ij}\big). $$

Its gradient is

$$ g_{ij} := \nabla_{q_i} C(q_i,q_j) = -\frac{W_c}{2w_c}\big(1-\tanh^2 z_{ij}\big)\frac{q_i-q_j}{R_c^2\,r_{ij}}, \qquad \nabla_{q_j} C(q_i,q_j) = -g_{ij}. $$

$C$ is symmetric, and its gradient is antisymmetric: $g_{ji} = -g_{ij}$. The defaults are $R_c = 0.8$ m, $W_c = 500$, $w_c = 0.1$ and $\varepsilon = 10^{-10}$.

Coupled running cost and Hamiltonian.

$$ L(\mathbf x,\mathbf u,t) = \sum_{k=1}^K L_k(x_k,u_k,t) + \sum_{i<j} C(q_i,q_j), \qquad H(\mathbf x,\mathbf p,\mathbf u,t) = \sum_{k=1}^K \Big[L_k(x_k,u_k,t) + p_k^\top f(x_k,u_k)\Big] + \sum_{i<j} C(q_i,q_j). $$

Optimal control is unchanged. $C$ does not depend on $\mathbf u$, so $\partial H/\partial u_k = 2Ru_k + [p_{k,5},p_{k,6},p_{k,7}]^\top$. Each agent therefore keeps the clipped single-agent minimiser $u_k^\star(x_k,p_k)$. The dynamics stay decoupled.

Costate equation: the only new term.

$$ \dot p_k = -\frac{\partial H}{\partial x_k} = -\underbrace{\Big(2Q(x_k-x_{r,k}) + \big[\nabla B_s + \nabla B_m;\,0_4\big] + h(x_k,p_k)\Big)}_{\texttt{dHdx7}(x_k,\,p_k)} \;-\;\Big[\textstyle\sum_{j\ne k} g_{kj}\,;\ 0_4\Big]. $$

The coupling enters only through the three position entries of each costate. Every agent's costate is pushed by the others' positions, so the canonical system of all K agents must be integrated jointly.

Objective, residual, derivatives. The objective is $\boldsymbol\Phi(\mathbf v) = \int_0^T L\,dt + \sum_k\phi_k(x_k(T))$, which includes the integrated pair penalty. There is no terminal coupling, so the transversality residual keeps its per-agent form:

$$ \rho_k = p_k(T) - 2Q_T\big(x_k(T)-x_{r,k}(T)\big). $$

The gradient and the curvature surrogate keep their form, $\nabla\boldsymbol\Phi = -\mathbf S_x^\top\boldsymbol\rho$ and $\mathbf M = \mathrm{sym}(-\mathbf S_x^\top\mathbf J_r)$. Now, however, $\mathbf J_r = \partial\boldsymbol\rho/\partial\mathbf v$ and $\mathbf S_x$ have nonzero off-diagonal blocks $\partial\rho_i/\partial v_j$ whenever agents i and j interact within the horizon. They are not block-diagonal any more. These are the dense $7K\times7K$ matrices the unchanged algorithm already forms in the decoupled case.

Per-iteration cost. - RHS evaluation: each evaluation costs $\mathcal O(K)$ for the agent terms and $\mathcal O(K^2)$ for the pair terms. - Sensitivities: with the 7K tangent directions, the sensitivities cost $\mathcal O(NK^2 + NK^3)$. The cubic part has a small constant (a 3-vector per pair). - Dense algebra: $\mathcal O(K^3)$, as before.

3. Implementation

mpc_multi_int.build_ss_int(M, K, N, dt, JX, col, napply):

  • Joint rollout. One lax.scan carries $Z_A\in\mathbb R^{K\times(2\cdot7+1)}$: per agent $[x_k, p_k, c_k]$, with $c_k = \int L_k$ exactly as in the decoupled object, plus a scalar $c_p = \int\sum_{i<j}C$.
  • Agent terms: the RHS is jax.vmap(JX.fz_aug) over agents, i.e. the core's per-agent dynamics, $-\partial H/\partial x$ and $L_k$, unchanged.
  • Coupling: the position entries of $\dot p_k$ get $-G_k$, with $G_k = \sum_{j\ne k}g_{kj}$, and $\dot c_p = \sum_{i<j}C$.
  • Integration: RK4 with the same sub-stage reference sampling as the core, so $\Phi = \sum_k(c_k+\phi_k) + c_p$.
  • Pair penalty (pair_penalty). It is vectorised over the $K\times K$ difference tensor with the diagonal masked out, which works for any K and gives exactly 0 for K = 1. ε keeps the masked diagonal square root differentiable.
  • API. The interface is identical to build_ss_multi: res, J, all, Jr, Sx, g, resx, roll_pred, roll_costate, warm, with flat agent-major 7K vectors and $X_r\in\mathbb R^{K\times(7+3n_m)\times(2N+1)}$. So hopf_lax_mpc_solve and ensure_jbatch run on it unchanged. roll_pred and roll_costate (the warm start) are joint rollouts too.
  • Self-test helpers. hamiltonian (the joint H) and costate_rhs (the joint $\dot{\mathbf p}$).

Closed loop (apply_step_int). - The plants are integrated per agent, as before. - Each agent accrues tracking and obstacle cost until its own arrival. - Each pair accrues the true collision penalty while at least one of its two agents is still active. - The minimum pairwise distance is recorded over every fine RK4 step. - Arrived agents stay in the problem: they keep flying and remain obstacles for the others.

Findings:

  • The coupling works. With the penalty, every pair stays above $R_c$ for the whole run, at 1.11–1.21 m minimum distance. The decoupled runs reach 0.65 / 0.31 / 0.12 m. All agents still reach their goals, 0.2–0.5 s later.
  • Price of separation. The tracking and obstacle cost rises by 11 %, 16 % and 83 % for K = 2, 3, 4. The pair cost itself stays small, because the agents keep the penalty mostly inactive: the closed loop anticipates encounters over the 1.1 s horizon rather than pushing through the barrier. For K = 4 the paths are reshaped along the whole course, not only at the encounters (figure above).
  • Solver. Every cycle of every run converged, with the certified stop of section 4 of the multi-agent README. The iteration count grows modestly (2.6 → 3.5 per cycle at K = 4). The saddle escape fired twice, at K = 4 (2 kicks), which is the expected pass-left-or-right symmetry.
  • Per-iteration cost is unchanged within timing noise. The joint rollout costs no more than the vmapped independent rollouts, because the sensitivities were already formed densely over all 7K directions in the decoupled object. The $\mathcal O(K^2)$ pair term is negligible at these K. The machine was not idle during these runs: the decoupled K = 2 baseline took 13.4 ms/iter here, against 9.7 ms recorded in ../multi_agent. Treat the timings as indicative only.

  • No penetration. The barrier coordinate $r$ never drops below 1.40. The barrier is at $r = 1$, and the light shell drawn in the figures is at $r = 1.25$.
  • What happens instead. In the decoupled run, agents 0 and 1 pass obs-1 nearly on top of each other: 0.19–0.23 m apart at t = 2–2.4 s, both at y ≈ −1.5. In the coupled run, agent 0 keeps to the outside (y ≈ −2.0). Agent 1, squeezed between agent 0 and obs-1, moves 0.45 m towards the obstacle and climbs 0.2 m. The climb shrinks obs-1's cross-section, so agent 1 can fly over its flank, and it increases the 3-D distance to agent 0 (1.18 m).
  • Why the trade is cheap. The altitude weight $Q_z = 2$ makes a 0.2–0.3 m climb cheap compared with the pair penalty.
  • Where to see it. The 3-D animations show the obstacles at their true height.

6. Remarks and limitations

  • Goal spacing vs $R_c$. The layout puts the goals on the line x = 20 with spacing 4/(K−1) m. For K ≥ 6 this is below $R_c = 0.8$ m, so the penalty would compete with reaching the goals. A K-sweep must scale $R_c$ below the goal spacing (for example $R_c \approx 0.35$ m for K = 10). --Rc sets it.
  • Soft, not hard. The penalty is a cost, not a constraint. Separation is not guaranteed; it is traded against tracking through $W_c$ and $w_c$.
  • Timing hygiene. The scaling numbers of ../multi_agent were taken on an idle machine. The runs here were not (see section 5), so compare ms/iter only within this table.

python mpc_testbed_multi_int.py --K 2,3,4 --nocol           # decoupled baselines (Wc = 0)
